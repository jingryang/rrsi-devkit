# 20-case 设计规则与骨架

> **20 例不是「自由发挥的组合矩阵」，而是一套固定骨架。**
> 同类 elementwise 算子之间，20 条 shape / dtype 序列 / value_range 几乎逐条一致 ——
> 差异只出现在语义确实要求不同的少数槽位上。
> 所以正确做法是：**先套用 §2 的骨架表，再按算子语义只改必须改的槽位。**

## 1. 设计维度（note 字段就是它的编码）

20 例按六个维度做正交覆盖：

| 维度 | 档位 | 20 例中的典型配额 |
|---|---|---|
| **dtype** | proto 声明的全集 | 循环轮转，必须全覆盖 |
| **规模** | S / M / L | 13 / 5 / 2 |
| **对齐性** | 对齐 / 非对齐 / 质数非对齐 | 5 / 9 / 6 |
| **值域** | 微小 / 小 / 中 / 大 × 对称 / 非对称 | 见骨架 |
| **维度数** | 1D ~ 5D | 至少 3 档；骨架覆盖 1/2/3/4/5D |
| **特殊值** | fp16边界 / fp32边界 / inf / nan / 零值 | 各 1 例，共 5 例（槽位 10~14） |
| **属性** | 每个 attr 的取值组合 | 每个 attr 至少 2 种取值 |


- 对齐 = 2 的幂（如1024、2048、8192）
- 非对齐 = 幂次 ±1（如1023、2049、8193、511、4097）
- 质数非对齐 = 质数（如1009、1021、1537、769、363/367/373、4001、1000003）

结构：槽位 1~5 对齐大规模、6~9 非对齐/质数、**10~14 五个特殊值**、15~20 补齐值域与维度。

### 套用骨架时必须按语义改写的地方

1. **值域必须落在算子定义域内**。例：
   - `sqrt` / `log` 的定义域是 x>0 → 把对称值域改成正区间（`[0.001, 1]`）
   - `asin` / `acos` 定义域是 [-1,1] → 全部值域收进 [-1,1]，大值域槽位改用 `[-1, 1]` 的不同分布
2. **特殊值槽位要符合算子语义**。若算子在 nan/inf 上无定义或下游不做该比对，
   保留槽位但换成该算子有意义的边界（例如整型算子换成 dtype 满量程）。
3. **dtype 序列换成 proto 实际声明的集合**。若算子存在整型输出，
   对应槽位只轮转 proto 实际声明的整型 dtype；若是混合输出，按输出角色分别取值，
   并让 `value_range` 匹配各自可表示范围或语义范围。
4. **有 attr 就在 note 尾部加属性段**，并保证每个 attr 至少 2 种取值、
   组合上与 dtype/规模正交（gelu 的 `approximate` 在 none/tanh 间交替即是范例）。

## 3. 多输入算子（L2/L3）的调整

- `input_shape` 每个输入一项，**顺序严格同 `proto.inputs`**。
- `value_range` 改用逐输入写法；权重/bias 类输入用更小的值域
  （conv_2d：x/filter `[-1,1]`，bias `[-0.1,0.1]` —— bias 值域约为其它输入的 1/10）。
- **shape 之间的耦合必须成立**，这是多输入算子最常见的失败点。conv_2d 为例：
  `x=[N,C_in,H,W]`、`filter=[C_out,C_in,K_h,K_w]`、`bias=[C_out]`，
  两处 `C_in` 必须相等、`bias` 长度必须等于 `C_out`。
- 规模要下调：多输入算子单例总元素数通常控制在 ~16M 以内（conv_2d 最大 16.8M）。
- 可选输入用 `null` 三列同位置占位（见 format-contract.md §2.2）。

## 4. 属性取值与「支持范围」的联动

`attrs` 的取值集合决定了 §3 支持范围表里对应行的**备注列**。两者必须自洽：

```
cases.yaml:  attrs: {approximate: none} / {approximate: tanh}   (两种都出现)
desc.md:     | `approximate` | {"none", "tanh"} | cases.csv 两种取值均覆盖 |
```

写完 cases.yaml 后，**支持范围的备注列一律从 cases 反算**，不要凭印象写。
`scripts/validate_preinput.py` 的 G8 会把两边对起来比。

## 5. 常见错误清单（都在真实产物里出现过，逐条自查）

| 错误 | 表现 | 拦截门 |
|---|---|---|
| 支持范围备注与 cases 不自洽 | 声称实测各维 ≤8192，实际存在 8193 | G8 |
| note 的维度标注与 shape 矛盾 | shape 是 2D `[1009,1021]`，note 却写 `5D` | 需人工核 |
| note 元素数口径不一致 | 多数按元素数、个别按字节数 | 需人工核 |
| yaml↔csv 漂移 | 单独改了 csv 没回写 yaml | G11 |
| inf 写成字符串 | 应写 `.inf`，写成 `'inf'` | G9 |
| 科学计数法漏 `+` | `3.0e38` 被 YAML 解析成字符串 | G9 |
| 缺 H3 子节 | 漏掉「数据类型」等必备小节 | G6 |
| proto 与 cases 属性错位 | 同一项在 proto 是 input、在 cases 当 attr 用 | G5 |
| 照抄 `cann_bench.` 调用约定 | 本仓无此包，示例跑不通 | G16 |
