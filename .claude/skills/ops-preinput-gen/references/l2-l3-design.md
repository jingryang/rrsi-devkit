# L2/L3 多输入算子设计规范

> **这份文件承载的是「程序管不了、但决定成败」的部分。**
>
> L1 单输入算子的正确性几乎可以被 16 道门完全约束（G14/G15 对单输入自动空操作）；L2/L3 不行 ——
> 跨输入 shape 耦合、语义不变量、索引合法性这些东西，程序只能校验
> 「有没有写下来」「有没有明显矛盾」，**判断不了写得对不对**。
> 所以 L2/L3 的质量取决于本文的设计规范被执行得如何。
>
> 本文是**规范**：下列写法与配额均为多输入算子的通行做法。

---

## 0. 先认清 L2/L3 的失败模式

`--run-golden` 实跑时，L2/L3 的失败**几乎全部**来自同一类原因 ——
通用随机造数造不出「合法的输入组合」：

```
AssertionError: Sum of expert_token_num_per_rank (66049) must equal A (16384)
RuntimeError:   The size of tensor a (256) must match the size of tensor b (4)
RuntimeError:   selected index k out of range
AssertionError: x=torch.float16 时 weight_scale / activation_scale 必须为 None
```

这四条正是 L2/L3 的四类隐性契约：**计数不变量、shape 耦合、索引合法性、dtype 联动**。

**关键推论**：下游 developer 造数时面临的困难和校验器完全一样。
如果这些契约没有写进 `desc.md`，下游只能靠猜 —— 这就是 L2/L3 成功率低的根因。
**所以对 L2/L3 而言，`desc.md` 把约束写全，比 cases 本身设计得漂亮更重要。**

## 1. 跨输入 shape 耦合 —— 必须显式建模

### 1.1 先定义符号维度，再用符号写 shape

L2/L3 算子的「支持范围」表应当用**符号维度名**（`N` / `C` / `K` / `E` / `M`）
做行名，而不是像 L1 那样写 `x 各维大小`。这是刚需：多输入算子的维度是**共享**的，
只有先给维度起名，耦合关系才写得出来。

```
x      : [N, C_in, H, W]
filter : [C_out, C_in, K_h, K_w]
bias   : [C_out]
```

然后表的每一行是一个**符号维度**，而不是某个输入的某一维：

| 维度 / 参数 | 范围 | 备注 |
|---|---|---|
| `N`（batch） | 1 ~ 256 | cases.csv 实测 2 ~ 8 |
| `C_in`（输入通道） | 1 ~ 2048 | cases.csv 实测 7 ~ 2048 |
| `C_out`（输出通道） | 1 ~ 2048 | cases.csv 实测 7 ~ 2048 |

### 1.2 表后必须有一行 `约束：`

多输入算子应在支持范围表后加一行独立的 `约束：`，集中声明跨输入关系。
G15 门会检查 3 输入以上的算子是否有这一行。

```markdown
约束：`C % num_groups == 0`；`gamma`、`beta` 的 shape 均为 `(C,)` 且 dtype 与 `x` 一致。
```

### 1.3 耦合模式库（直接对号入座）

| 模式 | 范例 | 不变量 |
|---|---|---|
| **归一化权重** | `group_norm`, `rms_norm` | `gamma.shape == beta.shape == (C,)`，C 取自 x 的通道维 |
| **卷积** | `conv_2d`, `depthwise_conv_2d` | `x[1] == filter[1]`(C_in)；`filter[0] == bias[0]`(C_out) |
| **矩阵乘** | `quant_matmul`, `grouped_matmul` | `x1[-1] == x2[0]`(K)；`bias` 长度 == N |
| **索引/聚集** | `gather`, `scatter` | `indices` 值域 ⊆ 被索引维；`updates.shape` 与 indices 对齐 |
| **逐元素多输入** | `maximum`, `gcd`, `apply_adam_w` | 全部输入 shape 完全相同（或可广播） |
| **MoE 路由** | `moe_*` | 计数不变量：`sum(tokens_per_expert) == M` |
| **量化** | `weight_quant_batch_matmul` | `antiquantScale` 长度 == weight 的输出维 |

> ⚠️ **陷阱**：若 conv 的 20 个用例**全部**取 `C_out == C_in`，
> 于是「20 例恒成立」的统计会额外推出 `x[1] == filter[0]` 这条**假耦合**。
> 这说明两件事：(1) 统计出的恒等式**不等于**语义必然，必须回到数学定义确认；
> (2) 设计 cases 时**应当让 `C_out != C_in`**，否则用例覆盖不到真实的通道变换。
> G15 只把耦合当"提示应写进文档"，绝不据此判 FAIL，正是因为这个陷阱。

## 2. 按输入角色分配值域

L1 的 value_range 82% 是共享写法；到 L3 只剩 28% —— **72% 必须逐输入写**。
因为不同角色的输入，合理值域差一个数量级甚至完全不同：

| 输入角色 | 值域策略 | 例 |
|---|---|---|
| **数据主体**（x, data, input） | 按 L1 骨架的值域档位走 | `conv_2d`: `[-1,1]` / `[-3,3]` / `[-0.1,0.1]` |
| **权重**（filter, weight） | 与数据主体同量级 | `conv_2d.filter` 与 `x` 同值域 |
| **偏置/缩放**（bias, scale, gamma） | **约为主体的 1/10** | `conv_2d.bias` = `[-0.1,0.1]` vs `x` = `[-1,1]` |
| **索引**（index, indices, segment_ids） | **`[0, 被索引维-1]`** | `gather.index` = `[0,1023]`，x 该维恰为 1024 |
| **概率/分数**（scores, probs） | 固定 `[0, 1]` | `nms.scores` 恒为 `[0,1]`，与 boxes 无关 |
| **缺省的可选输入** | `null` 三列同位占位 | `quant_matmul` 的 offset/pertoken_scale |

**索引值域是唯一可程序化的一条**（G14 门）：索引输入应满足
`hi + 1 ∈ {某个真实维度大小}`。上界也可以是**维的乘积**
（`moe_finalize_routing` 的 `[-1, E*C-1]`），以及用 **`-1` 作无效索引哨兵**——
后者是有意的设计，必须在 desc.md 单开小节写明。

## 3. 语义不变量 —— 程序完全管不了，只能靠文字

这是 L2/L3 最难、也最容易被跳过的部分。典型不变量：

| 类型 | 例子 | 必须写在哪 |
|---|---|---|
| **计数和** | `sum(group_list) == M`；`group_list` 严格非递减且末值 == M | 规则与约束 + 支持范围 `约束：` |
| **整除** | `C % num_groups == 0` | 同上 |
| **单调/有序** | `group_list` 非递减；`unique` 输出升序 | 规则与约束 |
| **索引合法** | `1 ≤ k ≤ x.shape[dim]`；`indices ∈ [0, N-1]` | 支持范围备注列 + `约束：` |
| **dtype 联动** | `x=fp16 时 weight_scale 必须为 None` | 数据类型小节 + 规则与约束 |
| **attr 互斥** | `split_item ∈ {0,1,2,3}` 决定输出形态 | 单开 `### <attr> 说明` 小节 |
| **可选输入组合** | 哪些可选输入可以同时缺省 | 输入参数说明 |

**写法范例**（以分组矩阵乘为例）：

```markdown
### 规则与约束

- **K 一致性**：`x.shape[1]` 必须等于 `weight` 中 K 维（`weight.shape[1]` 或
  `weight.shape[2]`，由 `transpose_weight` 决定）
- **N 一致性**：所有 expert 共享同一 `N`
- **group_list**：长度等于 `E`，严格非递减，最后一个值等于 `M`
- **空组**：允许 `group_list[i] == group_list[i-1]`，对应 expert `i` 不参与计算
```

四条特征值得学：**加粗小标题分类**、**用符号维度**、**写清取值来源**、
**显式声明边界情形（空组）是合法的**。

### 何时该单开一个 H3 小节

当某个 attr 会**改变输入/输出的形态**时，单开 `### <attr> 说明` 并配表。
例如分组矩阵乘的 `### split_item 取值` / `### group_list 语义`，
MoE 路由的 `### drop_pad_mode 说明`（含一张「模式 × 索引范围」表）。
这类算子如果只在 bullet 里带一句，下游必然造错数。

## 4. L2/L3 的 20-case 设计

### 4.1 与 L1 的差异

| 维度 | L1 | L2 | L3 |
|---|---|---|---|
| 单例总元素中位数 | 2.86M | 3.93M | **1.99M**（更小，因为输入多） |
| S / M / L 均值 | 11.5 / 6.2 / 2.3 | 9.5 / 7.0 / 3.5 | 9.0 / 4.9 / 2.0 |
| 共享 value_range 占比 | 82% | 44% | **28%** |

**L3 的规模反而更小**：输入多，总内存是各输入之和，单个输入必须收着点。
多输入算子单例总元素数建议控制在 **~16M 以内**。

### 4.2 覆盖矩阵要多两个维度

L1 的六维（dtype × 规模 × 对齐性 × 值域 × 维度数 × 特殊值）之外，L2/L3 还要覆盖：

7. **耦合维度的取值组合** —— 让耦合维取不同值，别所有例都相等
   （`C_out != C_in`、`K != N`、`M` 非 2 的幂）
8. **可选输入的在场/缺省组合** —— 每个可选输入至少 1 例缺省、1 例提供
   （`quant_matmul` 的 offset/pertoken_scale/bias 即如此轮转）

并且要保留**边界情形**用例：空组（`m_i == 0`）、单元素（`num_segments=1` 全归约）、
无效索引哨兵（`-1`）。这些是 L2/L3 最容易出 bug 的地方，应专门留槽位。

### 4.3 特殊值用例的取舍

L1 固定 5 个特殊值槽位（fp16边界/fp32边界/inf/nan/零值）。L2/L3 要按语义裁剪：

- **索引类输入不写 inf/nan** —— 整型没有这些值。对应槽位改成
  「索引边界」（取 0 和 N-1）或「无效索引」。
- **多输入算子的 inf/nan 通常只施加在数据主体上**，权重/索引保持合法
  （`conv_2d` 的 inf 例是三个输入同时 inf，但那是因为三者都是浮点数据）。
- **计数类输入（group_list）永远不能是特殊值** —— 它必须满足计数不变量。

## 5. L2/L3 生成检查清单

写完后逐条自查（G14/G15 只能覆盖其中 2~3 条）：

- [ ] 符号维度已定义，`desc.md` 的 shape 用符号表达（`[N, C_in, H, W]`）
- [ ] 支持范围表的行名是**符号维度**，不是「x 各维大小」
- [ ] 表后有 `约束：` 行，集中声明跨输入关系（≥3 输入必须有）
- [ ] 每一条 shape 耦合都能在「规则与约束」里找到对应文字
- [ ] 每一条语义不变量（计数和/整除/单调/索引合法/dtype 联动）都已写明
- [ ] 改变形态的 attr 单开了 `### <attr> 说明` 小节
- [ ] 索引类输入值域 = `[0, 被索引维-1]`，或已写明其它来源（乘积/attr/哨兵）
- [ ] bias/scale 类输入值域约为数据主体的 1/10
- [ ] 20 例中耦合维度取了**不同**值（别全用 `C_out == C_in`）
- [ ] 每个可选输入至少各有 1 例缺省与提供
- [ ] 保留了边界情形用例（空组、单元素、无效索引）
- [ ] 单例总元素数 ≤ ~16M
- [ ] `--run-golden` 若报 `G13-unsynth`，逐条确认该不变量**已在 desc.md 写明**

最后一条尤其重要：**`G13-unsynth` 是 L2/L3 的核心信号**。
它列出的每一条「通用造数满足不了的约束」，都是下游 developer 同样会撞上的坑。
看到它不要当噪音略过 —— 去 `desc.md` 确认这条约束写清楚了没有。
